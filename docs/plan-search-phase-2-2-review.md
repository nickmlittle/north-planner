# Plan search review (item 2.2)

**Agreed behavior:** Search matches item names, categories, owners, account names/providers/types and pots. Active owner, category and Transfers destination filters constrain results. Query and filters remain while the mounted page switches views, and reset on reload. Search results are flat rows with owner and category context. Clearing search keeps filters changed during search and restores the prior browsing scroll position.

The Plan table switches to direct item results as soon as a nonblank query is entered. Result rows retain the existing item, amount and action controls. A status line explicitly labels the matching count and total, and the table caption identifies matching items. A clear button sits beside the search field; the no-results message names the current filters and suggests clearing or changing the query. Clearing restores the previous grouped browsing view and its expansion state. Search ignores surrounding whitespace and remains case insensitive.

The browser captures the page or workspace scroll offset before the first search input, including a pointer press before focus can move the viewport. On clearing, it restores that offset for the same month and destination scope; different months/scopes do not reuse an old position. The clear action returns keyboard focus to the search field. Opening or cancelling an item editor leaves the mounted search state in place.

Automated tests cover broad destination matching, direct results, context and matching totals, no-results state, clear-search restoration, filter retention and the existing Plan/Transfers view switch. Desktop Chrome was inspected with the synthetic baseline fixture: searching Groceries showed one directly openable item, the matching £330.47 total and “Joint · Home” context. The iPhone 17 simulator loaded the fixture, but its remote keyboard did not reliably enter the test query during this inspection; mobile search behavior is covered by component tests rather than claimed as a completed touch-keyboard check. No saved budget, schema or calculation changes are involved.
